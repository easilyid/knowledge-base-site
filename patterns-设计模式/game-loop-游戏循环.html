游戏循环（Game Loop）

核心思想

游戏的核心驱动——循环执行”处理输入 → 更新世界 → 渲染”，独立于硬件速度。游戏循环解耦了游戏速度与硬件速度：不管硬件跑多快多慢，游戏逻辑按自己的节奏推进。这是游戏与传统的基于事件的 GUI 程序的根本区别——游戏不等待用户操作，而是主动轮询、持续模拟。

GPP 关键洞察：游戏循环是游戏的”心跳”。每个游戏都有一个，即使你从未显式写过——Unity 的 PlayerLoop 就是引擎级游戏循环。理解游戏循环就是理解游戏的运行模型。

问题动机

没有游戏循环时，基于事件驱动的程序无法保证每帧更新——用户不操作时世界冻结：

这种写法的问题：

  • 世界静止：用户不操作时游戏世界冻结，敌人不移动、动画不播放、物理不模拟
  • 速度依赖硬件：如果没有 deltaTime 机制，快机器上游戏飞速、慢机器上龟速
  • 无法处理持续输入：摇杆、方向盘等模拟输入是持续的，不是离散事件

游戏循环的核心动机：让游戏世界持续运转，且运转速度与硬件性能无关。

游戏开发深度

Unity 的 PlayerLoop 就是游戏循环

Unity 的 PlayerLoop 是 C++ 层的游戏循环，每帧按固定顺序执行各子系统。开发者通过 MonoBehaviour 的生命周期方法挂载到 PlayerLoop 的各个阶段：

PlayerLoop 是 Unity 的心脏

PlayerLoop 决定了所有 Unity 子系统的执行顺序。自定义 PlayerLoop 可以插入自己的子系统，但极少需要。参见 player-loop-主循环。

固定时间步 vs 可变时间步：FixedUpdate vs Update

Unity 同时提供两种时间步——FixedUpdate 用固定步长，Update 用可变步长：

维度FixedUpdate（固定）Update（可变）
步长Time.fixedDeltaTime（默认 0.02s = 50Hz）Time.deltaTime（实际帧间隔）
调用频率与帧率无关，按累积时间补发每帧一次
适用场景物理模拟、碰撞检测输入处理、UI、动画、游戏逻辑
确定性高（步长恒定）低（步长波动）
螺旋死亡风险有（帧率低于固定步长时）无

参见 player-loop-主循环 了解 PlayerLoop 中 FixedUpdate 与 Update 的精确调度。

时间累积器（Accumulator）模式

时间累积器解耦渲染帧率和物理帧率——物理按固定步长执行，渲染按实际帧率执行：

targetFrameRate 不影响物理

Application.targetFrameRate 只限制渲染帧率，FixedUpdate 的频率由 Time.fixedDeltaTime 控制。即使渲染降到 30fps，FixedUpdate 仍以 50Hz（默认）运行——Unity 会在一帧内执行多次 FixedUpdate。

变体与演进

变体说明适用场景
固定步长逻辑更新使用恒定步长，确定性保证物理模拟、网络同步、回放
可变步长逻辑更新使用实际帧间隔，流畅但不确定单机游戏、UI 交互
固定步长 + 可变渲染物理用固定步长，渲染用可变步长 + 插值大多数游戏的最佳平衡——Unity 的选择
解耦更新与渲染逻辑和渲染在不同频率运行网游服务器（高逻辑频率）、客户端（低渲染频率）

解耦更新与渲染

反模式

在 Update 中用 deltaTime 驱动物理

Update 的 deltaTime 是可变的。在 Update 中直接操作 Rigidbody（如 AddForce、MovePosition）会导致物理行为随帧率波动。所有 Rigidbody 操作应在 FixedUpdate 中执行。参见 player-loop-主循环。

固定时间步的螺旋死亡（Spiral of Death）

帧率低于固定步长频率时，一帧内需要执行多次 FixedUpdate 来”追赶”。如果 FixedUpdate 本身计算量很大，追赶会导致帧率进一步下降，需要更多 FixedUpdate……形成恶性循环。解决方案：限制最大帧时间（Time.maximumDeltaTime，默认 0.333s），或在一帧内限制 FixedUpdate 最大执行次数。

帧率依赖的游戏逻辑

如果游戏逻辑不用 deltaTime 缩放，在 120fps 设备上游戏速度是 60fps 设备的两倍。所有与时间相关的计算（移动、冷却、计时器）都必须乘以 deltaTime。参见 update-method-更新方法。

权衡与选择

  • 用固定时间步：需要确定性（物理、网络同步、回放）
  • 用可变时间步：需要流畅体验（动画、UI）
  • 用半固定：大多数游戏——Unity 的默认方案
  • 用解耦更新/渲染：网络多人游戏
