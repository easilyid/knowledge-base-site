Unity 可释放资源与 SafeHandle

核心思想

Unity 中有两类需要确定性释放的资源：（1）实现了 IDisposable 的 native container（NativeArray 等）；（2）不实现 IDisposable 但有自己释放方法的 GPU/引擎资源（ComputeBuffer、AssetBundle 等）。此外，Object.Destroy 和 IDisposable.Dispose 是两个完全不同的生命周期模型，混淆是常见错误来源。

Allocator.TempJob 4 帧超时

Allocator.TempJob 分配的内存必须在 4 帧内释放，否则 native code 打印警告。这是 Job System 内部的假设——TempJob 内存是短命的，超过 4 帧暗示逻辑错误。

ComputeBuffer 不 Release 会崩溃

不手动 Release() ComputeBuffer 会导致 standalone 崩溃。这不是”可能泄漏”级别，是”必崩”级别。

AssetBundle 卸载

AssetBundle 不能部分卸载

一个 AssetBundle 中的所有 asset 要么全在内存中，要么全卸载。你不能只卸载 bundle 中的一个 asset。这就是 Addressables 引用计数系统存在的原因——它跟踪 bundle 内每个 asset 的使用情况，在 bundle 的所有 asset 引用归零后才卸载整个 bundle。

Object.Destroy vs IDisposable

Unity Object.Destroy 和 IDisposable.Dispose 是两个完全不同的生命周期模型：

维度Object.DestroyIDisposable.Dispose
触发方引擎内部 + 用户代码仅用户代码
线程只能在主线程调用任何线程
对象类型UnityEngine.Object 子类任何 IDisposable 实现
效果标记对象为”已销毁”，实际销毁延迟到帧末立即释放资源
null 检查if (obj) 检查 Unity 生命周期而非 C# null标准 C# null 检查

统一管理模式

如果一个 MonoBehaviour 同时持有 IDisposable 资源和 Unity Object 资源，推荐在 OnDestroy / OnDisable 中统一释放，而不是让类实现 IDisposable——因为 Unity 的生命周期回调由引擎驱动，比 Dispose 更可靠。

SafeHandle 深入

SafeHandle 是 .NET 2.0 引入的可靠性原语，替代手写 finalizer 管理 OS 句柄。

为什么 SafeHandle 比手写 finalizer 更好

问题手写 finalizerSafeHandle
句柄回收竞争finalizer 和 P/Invoke 并发时，句柄可能被 OS 回收再分配给其他对象，导致操作错误句柄内部引用计数，P/Invoke 调用期间自动增减计数，防止句柄被提前关闭
AppDomain 卸载可靠性普通 finalizer 在 AppDomain 强制卸载时可能不执行继承自 CriticalFinalizerObject，finalizer 保证在 AppDomain 卸载时执行
Finalizer 顺序不可控关键 finalizer 保证在普通 finalizer 之后执行
线程安全手写 GC.KeepAlive 易错P/Invoke 参数声明为 SafeHandle 时，运行时自动保证句柄存活
句柄类型安全raw IntPtr 可以传错句柄类型派生类提供类型安全（SafeFileHandle vs SafeWaitHandle）

SafeHandle 子类实现

CER（Constrained Execution Region）

CER 是 .NET 的可靠性保证机制，确保一段代码不会被异步异常（如 ThreadAbortException、OutOfMemoryException）打断。SafeHandle.ReleaseHandle() 运行在 CER 中：

  • 运行时在进入 CER 前预编译好所有代码（RuntimeHelpers.PrepareConstrainedRegions）
  • CER 内的代码不能分配托管内存、不能获取锁、不能调用虚方法（除非已 prepare）
  • 如果 ReleaseHandle 返回 false，会触发 releaseHandleFailed MDA 帮助诊断

SafeMemoryMappedFileHandle内存映射文件继承上述判定
CriticalHandle更轻量但不带引用计数（不推荐）自定义

SafeHandle 在 Unity 中的使用

Unity 游戏代码很少直接 P/Invoke OS API，因此手写 SafeHandle 子类的需求不多。但当你在 Unity 中调用自定义 native plugin（.dll/.so/.bundle）时，应该用 SafeHandle 包装返回的句柄，而不是用 IntPtr + finalizer。
