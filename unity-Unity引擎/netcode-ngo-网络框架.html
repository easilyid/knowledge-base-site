Unity Netcode for GameObjects（NGO）

是什么

Unity Netcode for GameObjects（简称 NGO）是 Unity 官方当前主推的多人联机解决方案，取代了已弃用的 MLAPI 和 UNet。它提供网络对象同步、RPC 通信、状态变量和物理/动画同步组件，基于 Server-Authoritative 模型设计。

NetworkBehaviour

NetworkBehaviour 继承自 MonoBehaviour，是所有网络脚本必须继承的基类。它提供网络生命周期的入口。

OnNetworkSpawn 与 OnNetworkDespawn

OnNetworkSpawn 是网络代码初始化的正确位置，替代 Awake / Start 中判断网络属性的写法。

调用顺序取决于生成方式：

生成方式调用顺序
动态生成（Instantiate + Spawn）Awake → OnNetworkSpawn → Start
静态放置（场景中预设）Awake → Start → OnNetworkSpawn

未 Spawn 时 Update 仍被调用

即使对象尚未 Spawn，Update / FixedUpdate / LateUpdate 仍会执行。必须加 if (!IsSpawned) return; 保护。

RPC

RPC（Remote Procedure Call）用于一次性事件通知，类似应用层协议。

ServerRpc 与 ClientRpc

命名规范：FunctionName + ServerRpc / ClientRpc。

可靠性与顺序

  • 默认可靠传输，保证同一 NetworkObject 上的 RPC 按触发顺序执行
  • 跨 NetworkObject 的可靠 RPC 不保证顺序
  • 频繁更新的 RPC 适合标记为不可靠：[ServerRpc(Delivery = RpcDelivery.Unreliable)]

主机调用 ServerRpc 立刻执行

当主机（Host）调用 [ServerRpc] 时，方法立即在本地执行，不经过网络队列。这与普通客户端的”存入队列、帧结束时发送”行为不同，容易产生逻辑 bug。

NetworkVariable<T>

NetworkVariable<T> 是服务器与客户端之间的状态同步机制，无需手动编写消息格式。

类型支持

支持情况说明
非托管类型直接支持（int、float、Vector3 等）
托管类型需实现 INetworkSerializable

权限控制

支持设置服务器端和客户端的读写权限，以及中途加入客户端的自动状态同步。

RPC vs NetworkVariable

维度RPCNetworkVariable
语义一次性事件持久状态
中途加入客户端不收到历史 RPC自动同步当前值
典型场景爆炸特效、聊天消息门开/关状态、玩家位置

用 RPC 控制持久状态会导致状态不一致

如果用 RPC 开门而不是 NetworkVariable 记录门的状态，中途加入的客户端看到的是关着的门。

NetworkTime 与 Ticks

NetworkTime

服务器和客户端之间存在传输延迟，产生两种时间视角：

  • LocalTime：本地时间流逝
  • ServerTime：对服务器时间的本地估计

Ticks

Ticks 类似 FixedUpdate，按固定速率运行，提供可注册的回调：

物理系统需要同步 Tick 速率

如果游戏使用 FixedUpdate 或物理引擎，应将 Tick 速率设为与 Fixed deltaTime 一致。

同步组件

NetworkTransform

自动同步 Transform，内部使用 NetworkVariable 实现。

  • Interpolate 选项：缓冲数据 + 平滑插值，使同步更流畅
  • 插值不应用于 Server → Host 和其他 Client 表现可能不一致
  • 可继承重写自定义同步逻辑

输入与逻辑分离

虽然有 NetworkTransform 自动同步，但官方教程中”输入→RPC→服务器处理→NetworkVariable 同步位置”的模式仍有价值：它将输入和逻辑处理分离，多人游戏中应尽量遵守此原则。

NetworkAnimation

自动同步 Animator 状态，仅适用于 Animator 蜘蛛网方案。

  • 内部只使用 RPC 同步（不使用 NetworkVariable）
  • 如果使用 Playable 动画系统，必须自定义同步系统：同步动画 ID、权重和 Transition 持续时间

NetworkRigidbody

依赖 NetworkTransform + Rigidbody，不做任何同步，只控制权限：

  • 无权限客户端的 Rigidbody 设为 kinematic，物理引擎不模拟
  • OnCollisionEnter 本地仍会触发，但跨联网实例的碰撞不会触发
  • 碰撞事件应在服务器监听，通过 ClientRpc 同步到客户端

反模式

在 Awake/Start 中判断网络属性

IsClient、IsServer 等属性在 Awake / Start 中可能不准确（取决于 Spawn 时机），应在 OnNetworkSpawn 中使用。

用 RPC 代替 NetworkVariable 管理状态

RPC 是瞬时事件，不持久。中途加入的客户端收不到历史 RPC，导致状态不一致。

忽略主机 ServerRpc 的即时执行特性

主机调用 ServerRpc 时立刻执行，不走网络队列。如果逻辑假设”ServerRpc 总是异步的”，会出 bug。

在 NetworkRigidbody 上依赖跨实例碰撞

联网实例间的碰撞不会触发 OnCollisionEnter，必须在服务器处理并通过 RPC 同步。
