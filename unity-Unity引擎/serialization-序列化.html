Unity 序列化系统（Unity Serialization）

是什么

Unity 序列化系统是引擎内置的将对象状态转换为可存储/传输格式（YAML / JSON / 二进制）的机制。它与 .NET 的 System.Runtime.Serialization 是两套独立系统——Unity 的序列化器直接操作字段，不经过属性，也不使用 ISerializable。

核心用途：

  • Inspector 中显示和编辑字段值
  • 保存 .asset、.prefab、.unity 场景文件
  • 运行时 JsonUtility 序列化/反序列化
  • 网络同步与存档系统的基础

字段序列化规则

哪些字段会被序列化

一个字段被 Unity 序列化器处理，需同时满足以下条件：

  1. public，或标注 [SerializeField]
  2. 非 static、非 const、非 readonly
  3. 字段类型必须可序列化

哪些类型可序列化

类型分类可序列化类型说明
基元int、float、double、bool、char、long、byte 等全部 numeric + bool + char
字符串string引用类型但特殊处理
枚举enum底层整数序列化
Unity 内建Vector2/3/4、Quaternion、Color、Rect、Bounds 等值类型，引擎直接支持
Unity 对象引用UnityEngine.Object 及其派生类存为 FileID + GUID 引用
自定义 struct/class标注 [Serializable] 的类型递归序列化所有可序列化字段
集合T[]、List<T>T 必须可序列化
固定大小缓冲fixed int buffer[16]（unsafe）仅在 unsafe 上下文中

不可序列化的类型

类型原因替代方案

交错数组 T[][]引擎不支持List<List<T>> 或扁平化
Nullable<T>引擎不支持单独的 bool hasValue + T value

[SerializeField] 与 [NonSerialized]

属性作用典型场景
[SerializeField]强制序列化 private 字段隐藏实现但需 Inspector 编辑
[NonSerialized]阻止序列化 public 字段运行时缓存、临时状态
[HideInInspector]序列化但不在 Inspector 显示内部数据，不想暴露给策划
[ReadOnly]⚠️ 非 Unity 内置序列化属性常被误用。Unity 内置序列化属性中没有 [ReadOnly]。常见来源：(1) Unity.Collections.ReadOnlyAttribute（Job System 用，非序列化）；(2) 自定义 PropertyAttribute。需自行实现或使用第三方库

[SerializeReference] — 多态与引用序列化

解决什么问题

Unity 默认序列化器对引用类型字段采用**内联（inline）**序列化——只保存字段声明类型的字段，丢失运行时实际派生类型的信息：

[SerializeReference] 改变了序列化策略：不再内联，而是存储为带类型信息的托管引用（managed reference）。

[SerializeReference] 支持的特性

特性说明
多态保存实际派生类型及其字段
null可以序列化 null 引用
共享引用同一个对象被多个字段引用时，只序列化一次，反序列化后仍共享
循环引用支持（但需注意深度限制）
接口类型IInterface 字段可序列化具体实现类

[SerializeReference] 的限制

不能用于 UnityEngine.Object 派生类

MonoBehaviour、ScriptableObject、GameObject 等 UnityEngine.Object 派生类不能用 [SerializeReference] 序列化。它们必须用常规引用字段（FileID + GUID）。

限制说明
不能用于值类型struct、enum、基元类型不能用——只能用于 class
不能用于 UnityEngine.Object 派生类只能用普通引用字段
引用不能跨宿主共享两个 MonoBehaviour 不能共享同一个 [SerializeReference] 对象
类型丢失如果引用的类被删除/重命名，Unity 标记为 “Managed references with missing types”
IL2CPP strip所有可能被序列化的派生类必须在 link.xml 或 asmdef 中保留
性能开销比内联序列化稍慢，复杂类型更明显

[SerializeReference] 与 IL2CPP

派生类被 IL2CPP strip

构建后运行时出现 TypeError 或 MissingMethodException 是常见症状。所有可能被序列化的子类必须在 link.xml 中保留，或使用 assembly definition 的 Preserve 属性。

序列化深度与限制

7 层嵌套限制

Unity 序列化器对内联序列化的嵌套深度有限制：最多 7 层。超过则深层字段被忽略。

深层嵌套字段静默丢失

超过 7 层的嵌套数据不会被序列化，也不会报错——只在 Inspector 中显示为默认值。这是最隐蔽的序列化 bug 之一。

循环引用

  • 内联序列化：直接自引用 → 字段被忽略；间接循环 → 10 层递归后截断
  • [SerializeReference]：支持循环引用，序列化为引用 ID

Null 引用

内联序列化的引用类型字段，反序列化时不可能为 null——Unity 总是创建一个默认实例。如果需要 null 作为有效状态，必须用 [SerializeReference]。

JsonUtility

JsonUtility 是 Unity 基于Internal序列化器的 JSON 工具——它不是通用 JSON 库，只支持 Unity 序列化器能处理的类型。

JsonUtility 限制

限制说明
不支持 Dictionary同序列化器限制
不支持多态没有类型信息，[SerializeReference] 的多态在 JSON 中丢失
不支持 object/接口同上
只处理 public 或 [SerializeField]同序列化器规则
不支持 KeyValuePair需自定义可序列化替代
需要 [Serializable]顶层类型必须标注

需要完整 JSON 功能时

如果需要多态 JSON、Dictionary 序列化、嵌套复杂结构，考虑使用 Newtonsoft.Json（Unity 2020+ 内置 com.unity.nuget.newtonsoft-json）或 System.Text.Json。但注意：这些库不走 Unity 序列化器，不处理 UnityEngine.Object 引用。

Prefab 序列化与 Override

Prefab 实例的序列化使用 Override 机制——只保存与 Prefab 源不同的值：

Override 的关键行为：

  • 修改 Prefab Asset → 所有未 Override 该字段的实例自动更新
  • 实例 Override 了某字段 → 不受 Prefab Asset 修改影响
  • PrefabUtility.GetPropertyModifications 可查看 Override 列表
  • 删除 Override → 恢复为 Prefab Asset 的值

反序列化与构造函数

Unity 反序列化与 C# 构造函数的交互

Unity 5.4+ 起，反序列化会调用无参构造函数，但调用时机和顺序与常规 C# 实例化不同：构造函数可能在加载线程上执行，且构造函数中设置的字段值会被反序列化数据覆盖。因此，不要在构造函数中初始化需要持久化的序列化字段——这些值会被覆盖。需要初始化的逻辑应放在 Awake / OnEnable / OnAfterDeserialize 中。

序列化在 DOTS 中的角色

DOTS/ECS 的序列化与经典 Unity 完全不同：

维度经典 Unity 序列化DOTS/ECS
数据载体MonoBehaviour / ScriptableObjectIComponentData (blittable struct)
存储格式YAML (.asset / .prefab)Binary / Entity Scene (.unity)
多态[SerializeReference]不支持（ComponentData 是值类型）
Inspector自动需 Authoring + Baker
引用FileID + GUIDEntity 引用 / BlobAssetReference

详见 ECS。

序列化事件与生命周期

反模式

在构造函数中初始化序列化字段

Unity 反序列化绕过构造函数，构造函数中的赋值不会生效。用 Awake 或 OnAfterDeserialize 代替。

用属性（property）期望被序列化

Unity 序列化器只读字段，不读属性。public int Health { get; set; } 不会被序列化。改用 backing field + [SerializeField]。

Dictionary 直接声明为序列化字段

public Dictionary<string, int> data; 不会被序列化，也不会报错——Inspector 不显示，数据静默丢失。必须用 ISerializationCallbackReceiver 转换。

深层嵌套超过 7 层

超过 7 层嵌套的 [Serializable] 内联数据静默丢失。用扁平化结构或 [SerializeReference] 替代。

派生类被 IL2CPP strip

构建后运行时 TypeError / MissingMethodException。所有被 [SerializeReference] 引用的派生类必须在 link.xml 中保留。

忽略反序列化的 null 语义

内联引用字段反序列化后永远不为 null（Unity 创建默认实例）。需要 null 语义时用 [SerializeReference]。

在 OnBeforeSerialize 中修改业务状态

OnBeforeSerialize 是序列化前的回调，不应有业务逻辑副作用。只用于数据格式转换。

JsonUtility 期望多态支持

JsonUtility 基于 Unity 内部序列化器，不支持多态和 [SerializeReference] 的类型信息。需要多态 JSON 时用 Newtonsoft.Json。
