Transform

是什么

Transform 是 Unity 中每个 GameObject 必带的组件，用来存储和操作位置、旋转、缩放以及父子层级关系。它既是空间变换数据，也是 Hierarchy 里的树节点——这种双重身份是理解 Transform 的关键。

Transform 不可移除、不可单独创建——它随 GameObject 创建而创建，随 GameObject 销毁而销毁。

父子层级

Transform 通过父子关系形成树结构——这就是 Hierarchy 窗口中看到的层级：

SetParent 的 worldPositionStays 参数：

  • true（默认）：保持世界空间位置/旋转不变，调整 local 值
  • false：保持 local 值不变，世界空间位置/旋转随父级变化

层级变换会传递

父对象的位置、旋转、缩放会影响子对象的世界空间位置——这是 Transform 的核心设计：

深层级 UI、骨骼动画、场景组织都依赖这套规则。Transform 内部维护了 localToWorldMatrix 和 worldToLocalMatrix 缓存，父级变换时自动传播到子节点。

Transform 性能：深层级与脏标记

Transform 内部使用脏标记（dirty-flag-脏标识）机制——修改 position/rotation/scale 时只标记脏，读取 world matrix 时才重算。但深层级时，父级变化会级联标记所有子节点为脏：

Unity 建议 Hierarchy 深度不超过 10-15 层。UI 中 RectTransform 层级更敏感，因为 Layout 系统还要做额外的尺寸计算。

SetParent 的隐藏成本

SetParent 不仅仅是改引用——它会触发层级结构的重算：

  1. 从旧父级移除 → 旧父级的子列表重建
  2. 插入新父级 → 新父级的子列表重建
  3. 如果 worldPositionStays: true → 计算 new local position/rotation
  4. 标记所有子节点脏 → 级联传播

对象池归还时应批量 SetParent(poolRoot, false) 而不是逐个操作。UI 对象的 SetParent 额外触发 Layout 重建（dirty-flag-脏标识），大量 UI 对象频繁切换父级是帧时间杀手。

Quaternion * Quaternion 的顺序等价于矩阵乘法——从右往左应用。rotA * rotB 表示”先 B 后 A”。如果结果不符合预期，大概率是顺序反了。

批量修改 Transform：EntityTransform 方案

大量对象同步修改 Transform 时（如阵型移动），逐个 transform.position = ... 会触发 N 次脏标记传播。Unity 2022+ 提供 EntityTransform 批量 API（实验性），或用 DOTS 的 LocalTransform 批量 System。

Transform 丢失与 NullReferenceException

transform 属性在 MonoBehaviour 中永远不会为 null（GameObject 必带 Transform），但以下场景会出现问题：

反模式

localPosition 和 position 混用

子对象在父级下移动时，localPosition 是相对父级坐标；position 是世界坐标。父级一变，二者关系也会改变。最常见 bug：在 SetParent 后读取 localPosition 但忘了 worldPositionStays 参数的影响。

非均匀缩放影响子层级

父级非均匀缩放（如 X=2, Y=1, Z=1）会让子对象变形、碰撞体形状不一致、物理计算不稳定。Unity 内部对非均匀缩放的处理路径更慢（无法优化为简单矩阵乘法）。UI 的 RectTransform 是特例——Canvas 自带非均匀缩放处理。

频繁重设父级可能有成本

大量对象在层级中频繁 SetParent 会触发层级重建和脏标记传播。对象池和 UI 列表是典型场景——应批量操作或用 SetParent(poolRoot, false) 减少重算。

在 FixedUpdate 中直接修改 Transform

有 Rigidbody 的对象应通过 Rigidbody.MovePosition / MoveRotation 移动，直接改 transform.position 会让物理引擎丢失碰撞和插值信息。只有在 isKinematic = true 且不需要物理碰撞时才可直接操作 Transform。

旋转用 eulerAngles 做计算

欧拉角的万向节锁和角度回绕（350° → 10° 的差值不是 340° 而是 20°）让计算出错。始终用 Quaternion API（Slerp、AngleAxis、LookRotation、Dot、Angle）做旋转逻辑。

2D 项目中 Z 轴旋转的陷阱

2D 项目中旋转通常是绕 Z 轴，但 transform.forward 在 2D 中指向 Z 轴负方向（屏幕内），不是”角色面朝方向”。2D 角色朝向应使用 transform.right（X 轴正方向）或自定义方向变量，不要混用 3D 方向常量。
