SceneManager

是什么

SceneManager 是 Unity 运行时管理 Scene 的 API 入口，负责加载、卸载、创建、查询和切换 active scene。它是 Unity 场景管理层的核心——理解 SceneManager 的加载模型是理解关卡切换、additive 场景架构、流式加载和跨场景通信的基础。

核心用法

兼容 Unity 6.4 及以上。Unity 2022 LTS 同样适用，API 一致。

关键细节

加载模式

模式行为适用场景
LoadSceneMode.Single卸载所有当前场景，加载新场景为唯一场景关卡切换、菜单→游戏
LoadSceneMode.Additive保留当前场景，新场景叠加到已加载集合分区加载、UI 覆盖层、子系统场景

Additive 加载的典型架构

大型项目常用”持久基础场景 + 按需 additive 子场景”模式：基础场景包含持久管理器、全局灯光、音频系统；内容场景（关卡、UI、战斗）按需 additive 加载/卸载。详见下方”场景架构模式”章节。

Multi-Scene Editing 工作流

Unity 编辑器支持同时打开多个场景（Multi-Scene Editing），这是 additive 加载在编辑器端的体现：

运行时复用相同结构——additive 加载各子场景。关键注意事项：

  • MergeScenes 是破坏性操作：SceneManager.MergeScenes(source, dest) 把 source 场景的所有 root GameObject 移到 dest 场景，然后 source 场景被销毁——此操作不可逆
  • MoveGameObjectToScene 限制：只能移动 root GameObject 到已加载场景，非 root 对象需先移到 root 再移动
  • Additive 加载后需刷新光照：Additive 加载场景后可能需要调用 LightProbes.Tetrahedralize() 重新计算光照探针
  • 遮挡剔除数据：Additive 加载的场景的遮挡剔除数据必须与主场景一起烘焙，否则运行时剔除不正确

加载 API 对比

API阻塞进度适用
LoadScene(name/index)是无小场景、启动场景
LoadSceneAsync(name/index)否AsyncOperation.progress大场景、加载画面
LoadSceneAsync + allowSceneActivation否可控带加载画面的场景切换

allowSceneActivation 与 0.9f 进度屏障

LoadSceneAsync 的 allowSceneActivation 标志控制场景加载的两阶段：

两阶段的实质：

  • 0 → 0.9：读取序列化数据、加载贴图/网格/音频等资源到内存（异步，不阻塞主线程）
  • 0.9 → 1.0：创建 GameObject 和 Component、调用 Awake/OnEnable/Start（同步，阻塞主线程）

allowSceneActivation 阻塞整个 AsyncOperation 队列

当某个 LoadSceneAsync 的 allowSceneActivation = false 时，它会阻塞 Unity 内部的 AsyncOperation 队列——其他 LoadSceneAsync 和 UnloadSceneAsync 操作即使已完成加载，也不会激活，直到前一个操作的 allowSceneActivation 设为 true。这意味着不能同时用 allowSceneActivation=false 来并行控制多个场景的激活时序——它们是串行队列。如需依次加载多个场景，应在前一个激活后再启动下一个。

progress 不会自动到达 0.9 以上

当 allowSceneActivation = false 时，progress 最高只到 0.9。设置 allowSceneActivation = true 后才会跳到 1.0 并完成。不要写 while (op.progress < 1f) 的等待循环——会死循环。

激活阶段（0.9→1.0）阻塞主线程

场景激活阶段执行所有新对象的 Awake/OnEnable/Start，这是同步操作。如果新场景中 Awake/Start 逻辑较重，会造成明显卡顿。优化策略：在 additive 加载的场景中保持 Awake/Start 尽量轻量，把重初始化逻辑延迟到后续帧。

卸载场景

UnloadSceneOptions

选项行为适用场景
None（默认）仅卸载场景层级中的 GameObject 和 Component常规卸载，保留共享资源
UnloadAllEmbeddedSceneObjects同时卸载场景序列化文件中嵌入的资源（贴图、网格、ScriptableObject 等）确保完全释放场景所有资源

UnloadSceneOptions.None 与共享资源

None 是默认值。它只销毁场景中的 GameObject/Component，不卸载场景序列化文件中嵌入的 native 资源（贴图、网格、音频等）。如果这些资源被其他场景引用，Unity 的引用计数系统会保留它们。但要真正释放不再被任何场景引用的 native 资源，需要额外调用 Resources.UnloadUnusedAssets()。

卸载后的资源释放

UnloadSceneAsync 可能返回 null

如果场景尚未完全加载（如还在 allowSceneActivation=false 状态），UnloadSceneAsync 可能返回 null。在访问返回的 AsyncOperation 前应做空检查。

卸载场景中的静态事件订阅必须清理

场景中的对象如果在静态事件（如 SceneManager.sceneLoaded、自定义静态事件）上注册了回调，必须在 OnDisable 中注销——而非 OnDestroy。原因：OnDestroy 不保证与场景卸载在同一帧执行，而 OnDisable 在对象禁用时立即触发。未注销的静态事件订阅会导致”空引用”异常和内存泄漏（GC 无法回收被静态引用持有的对象）。

卸载场景时协程被中断

场景卸载时，该场景中所有 MonoBehaviour 上的协程会被强制停止。如果协程正在执行关键操作（如保存进度），应在 OnDisable 中完成或使用 async/await 配合 CancellationToken。

DontDestroyOnLoad 与场景卸载

DontDestroyOnLoad 把 root GameObject 移到一个隐藏的持久场景（DontDestroyOnLoad 场景），使其不受 LoadSceneMode.Single 和场景卸载的影响：

DontDestroyOnLoad 的时序陷阱

DontDestroyOnLoad 只对 root GameObject 有效。如果对象不是 root，调用不会报错但也不起作用。此外，对象从源场景移到 DontDestroyOnLoad 场景后，其 gameObject.scene 会改变。如果源场景在对象移走前就被卸载（如 Awake 中没有立即调用 DontDestroyOnLoad），对象可能被误销毁。建议在 Awake 中尽早调用 DontDestroyOnLoad，或使用 MoveGameObjectToScene 显式移到持久场景。

Scene 结构体

Scene 是一个 struct（值类型），包含场景的标识信息但不持有对象引用：

handle — 非持久标识符

handle 是 Unity 引擎内部的场景标识符，用于比较 Scene 是否相等（Scene 的 == 运算符基于 handle）。关键特性：

  • 非持久：同一个场景文件每次加载会获得不同的 handle
  • 唯一性：运行时每个已加载场景的 handle 互不相同
  • 不跨会话：退出 Play Mode 后 handle 失效

buildIndex 与 AssetBundle 场景

  • Build Settings 中的场景：buildIndex 为序列整数（0, 1, 2…），与 Build Settings 窗口中的顺序一致
  • AssetBundle / Addressables 加载的场景：buildIndex 为 -1，因为这些场景不在 Build Settings 中
  • 运行时创建的场景：buildIndex 也为 -1

按 build index 加载很脆弱

场景列表重排会改变 index。大项目优先使用路径或明确的场景资产引用策略。LoadScene(0) 一个月后可能不再是启动场景。

Scene 是 struct 不是 class

Scene 是值类型——赋值和传参时是拷贝。但它内部的 handle 指向引擎内部场景数据，所以拷贝的 Scene 仍然可以用于查询和操作。Scene 的 == 比较基于 handle。

RuntimeInitializeOnLoadMethod 与场景加载时序

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)] 标记的方法在任何场景的 Awake 之前执行——适合做全局初始化（如依赖注入容器、日志系统）。AfterSceneLoad 则在场景的第一个 Awake 之后执行。

动态创建场景

动态场景不依赖 Build Settings 中的场景列表——适合运行时生成的 UI 层、调试面板等。

Additive 场景与 Active Scene

Active Scene 决定两件事：新创建的 GameObject 属于哪个场景，以及场景级光照设置（Ambient Light、Fog 等）：

Active Scene 影响光照和渲染

Active Scene 的光照设置（Ambient Light、Fog 等）会影响渲染结果。Additive 加载后如果忘了切换 active scene，新场景的光照可能不正确。应在 additive 加载后显式 SetActiveScene 到新场景（如果新场景包含自己的光照设置）。

additive 加载后忘记设置 Active Scene

Additive 加载新场景后，active scene 仍然是原来的。新创建的 GameObject 会进入旧场景而非新场景。加载后应显式 SetActiveScene。

编辑器专用 API

SceneManager 不用于 Editor authoring

SceneManager 主要用于 Player 和 Play mode。Editor 场景编辑应使用 EditorSceneManager。混用可能导致编辑器状态不一致。SceneManager.LoadScene 在 Edit mode 中会抛出 InvalidOperationException。

preventCrossSceneReferences

EditorSceneManager.preventCrossSceneReferences 默认为 true，Unity 会在 Inspector 中阻止跨场景拖拽引用。设为 false 可以允许编辑器中建立跨场景引用（用于编辑器工具），但这些引用仍然无法序列化——场景保存时会丢失。

ECS SubScene

详见 场景架构模式 - ECS SubScene。SubScene 在编辑器中使用 EditorSceneManager 管理场景文件，运行时通过 ECS 的 SceneSystem 加载实体场景数据——不经过 SceneManager。详见 ECS。

反模式

按 build index 加载很脆弱

场景列表重排会改变 index。大项目优先使用路径或明确的场景资产引用策略。LoadScene(0) 一个月后可能不再是启动场景。

只用文件名可能重名

不同目录下可能有同名 scene。使用完整路径（Assets/Scenes/Game.unity）能避免歧义。GetSceneByName 也可能返回同名场景中的错误一个。

卸载含 DontDestroyOnLoad 对象的源场景

DontDestroyOnLoad 把对象移到一个隐藏的持久场景中，但如果对象在被移走前其源场景被卸载，可能产生时序问题。应在 Awake 或 Start 早期调用 DontDestroyOnLoad，或使用 MoveGameObjectToScene 显式移到持久场景。

additive 加载后忘记设置 Active Scene

Additive 加载新场景后，active scene 仍然是原来的。新创建的 GameObject 会进入旧场景而非新场景。新场景的 Ambient Light 和 Fog 也可能不正确。加载后应显式 SetActiveScene。

跨场景引用在运行时断裂

场景 A 中的对象引用场景 B 中的对象——当场景 B 卸载后，引用指向已销毁对象。Unity 不提供跨场景引用的自动保护。additive 架构中应通过事件/接口解耦，或使用 ScriptableObject 作为中介。

同步 LoadScene 阻塞主线程

LoadScene（非 Async 版本）会阻塞主线程直到加载完成——对大场景可能导致数秒卡顿。非必要不用同步加载，特别是从菜单切换到游戏场景时。

sceneLoaded 中假设 Start 已完成

sceneLoaded 在所有 Awake/OnEnable 之后触发，但 Start 延迟到首次 Update 前。如果 sceneLoaded 回调依赖其他对象 Start 初始化的结果，可能时序不对。应改用 Start 中的显式初始化或事件通知。

卸载场景时未清理静态事件订阅

场景对象的静态事件订阅必须在 OnDisable 中注销，不是 OnDestroy。OnDestroy 不保证在场景卸载的同一帧触发。未注销的订阅导致空引用异常和内存泄漏。

UnloadSceneAsync 后未调用 Resources.UnloadUnusedAssets

UnloadSceneAsync 只销毁场景中的 GameObject/Component，不释放不再被引用的 native 资源（贴图、网格、音频）。对于 UnloadSceneOptions.None，需要额外调用 Resources.UnloadUnusedAssets() 来释放 native 资源。

allowSceneActivation 阻塞 AsyncOperation 队列

allowSceneActivation = false 会阻塞整个 AsyncOperation 队列，导致后续的 LoadSceneAsync 和 UnloadSceneAsync 也无法完成。不能用它来同时控制多个场景的激活——必须串行处理。
