ET Framework（ET 游戏框架）

是什么

ET Framework 是开源 C# 双端游戏框架（egametang，2017+），采用单线程多进程 + 自研 ECS架构。客户端和服务端共享代码，是中国 Unity 生态中唯一真正成熟的双端框架。

与 TEngine 的 OOP 服务定位器范式形成根本对立——TEngine 是”模块+接口+继承”，ET 是”实体+组件+静态系统”。

演进历史与架构

ET 9（最新）已经从”项目内单体仓库”演进为 package-based 架构：所有功能拆分为 cn.etetet.* 包（core / db / login / map / aoi / behaviortree / lockstep 等 30+ 包），通过 Unity Package Manager 管理。

ECS 实现（源码验证）

核心创新：Entity == Component

ET 的”实体即组件，组件即实体”不是口号——源码层面 Entity 和 Component 是同一个基类：

Entity 既有 children 也有 components——同一个对象可以挂另一个 Entity 作为子节点（Child），也可以挂另一个 Entity 作为组件（Component）。区别只在 IsComponent flag 和 Id 生成策略。

创建方式（源码）

Type 标识：RuntimeTypeHandle.Value

Components 用 Dictionary<long, Entity> 存储，key 是 Type 的 RuntimeTypeHandle——这比 Type 对象本身做 key 更快（避免 GetHashCode 调用）。

Publish（事件，多对多）

设计要点：

  • 事件参数 T : struct → 编译期保证零装箱
  • 按 SceneType 过滤 → 双端共享代码但事件不互相污染
  • 编译期通过 [Event] Attribute + Source Generator ([CodeProcess]) 自动注册

Invoke（函数式调用，一对一）

适用场景：跨平台差异化实现（如 Config 在客户端/服务端加载方式不同）、按 ID 分发（如 Timer）。

ETTask vs UniTask 的关键差异：

维度ETTaskUniTask
设计目标服务端 + 客户端通用Unity 专用
Context 传递内置 TaskType.WithContext 机制通过 CancellationToken

为什么 ET 不直接用 UniTask？因为 ET 的服务端代码也要用，而 UniTask 依赖 Unity。

Fiber：单线程多进程的真相

ET 宣称”单线程多进程”，但实际上是单进程多 Fiber，每个 Fiber 单线程：

每个 Entity 操作都会 DEBUG 模式下检查是否在正确的 Fiber 线程——这是 ET 实现”无锁并发”的核心机制：Fiber 之间用消息通信，单 Fiber 内单线程。

与 TEngine 的范式根本差异

维度TEngine（OOP）ET（ECS）
抽象单元Module（功能服务）Entity（数据 + 组件树）
组合方式接口实现 + 继承Entity.AddComponent / AddChild
行为定义类的方法静态扩展方法 ([EntitySystem])
数据存储实例字段Entity 是数据，System 无状态
多态机制虚函数 / 接口EventSystem 分发
通信方式GameEvent 全局总线Publish (跨模块) / Invoke (同模块)
异步UniTaskETTask
状态管理Module 类内字段Entity 上的 Component
适用场景中小客户端双端 + 大型分布式

适用判断

选 ET 的硬条件：

  • 需要前后端共享代码
  • 需要分布式服务器架构
  • 团队能接受 ECS 思维模式
  • 项目周期长，能承受高学习曲线

不选 ET 的理由：

  • 纯客户端项目（TEngine 更简单）
  • 团队习惯 OOP，ECS 学习成本太高
  • 不需要分布式（杀鸡用牛刀）
  • 想用 Unity 官方生态（ET 对 Unity 特定 API 解耦）

反模式

在 Model 层写逻辑函数

Model 层只能放数据字段声明。逻辑必须在 Hotfix 层的静态扩展方法中。

在 Hotfix 层声明数据字段

Hotfix 的 System 是静态类 + 扩展方法，不允许实例数据字段。

在 Model/Hotfix 中调用 Unity API

Model/Hotfix 必须与 Unity 引擎解耦，涉及引擎代码只能在 ModelView/HotfixView。
