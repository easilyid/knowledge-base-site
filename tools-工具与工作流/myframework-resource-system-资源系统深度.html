MyFramework 资源系统深度分析（Resource System Deep Dive）

是什么

MyFramework 的资源系统是一个“统一资源访问门面”：业务侧通过 ResourceManager 访问资源，底层根据运行环境选择 AssetDataBaseLoader 或 AssetBundleLoader。编辑器下可以走 AssetDatabase，打包后强制走 AssetBundle。

设计判断

优点

  • 业务 API 简单，隐藏 Editor/AB 差异。
  • 资源引用用 token 管理，能配合对象池自动回收。
  • loadGameResourceAsyncSafe 对 UI/特效异步加载很实用。
  • 打包工具和运行时加载器形成闭环：Editor 生成 STREAMING_ASSET_FILE，运行时读取它。

风险

路径字符串是强约束

加载 API 依赖 GameResources 下相对路径并要求带后缀，且不允许反斜杠。路径错误运行时才暴露。

AssetBundle 配置文件是单点

如果 STREAMING_ASSET_FILE 丢失或版本不一致，运行时资源映射会整体失效。

自研 AB 管线维护成本高

相比 YooAsset，MyFramework 自己处理 Bundle 名、依赖、下载、配置、卸载。控制力强，但需要长期维护各种边界条件。

与 TEngine / YooAsset 对比

  • TEngine 选择 YooAsset，复用成熟资源包、版本、下载、缓存策略。
  • MyFramework 选择自研 AB 管线，控制力更强，和自己的打包/热更/检查工具深度绑定。
  • 如果团队资源有限，YooAsset 路线维护成本更低；如果要完全掌控构建产物和工具链，MyFramework 路线更一致。
