决策 10：UI 系统

这是什么问题

UI 是项目里变更最频繁、代码量最大、和业务最纠缠的子系统。决策 10 决定你的 UI 系统抽象层次和心智模型——不是”用 UGUI 还是 UI Toolkit”那种引擎层选择。

选项

选项抽象层次代表典型场景
A. 业务薄抽象（Form/Panel 1 层）极低GameFramework / 自研薄壳单机/休闲、< 30 个界面
B. 栈+层管理（Window+Widget 2 层）中TEngine UIModule中国手游主流、30-200 个界面、热更
C. MVC 数据绑定（Panel+Data 2 层）中QFramework UIKit设计师配置、双向绑定需求
D. 桌面级组件化（5 层抽象）高BigCat WindowMgrMMO 客户端 / 编辑器 / 多桌面切换
E. ECS 实体化高ET 自研 UI决策 0 选了 ECS 时

必须避开的设计陷阱

Form/Window/Panel 类堆 1000 行业务逻辑

这是所有 UI 框架最常见的失败模式。Window 应该只管”我何时打开/关闭、组件怎么组装”，业务逻辑放 Controller / Component / 业务 Singleton。 bigcat-framework-BigCat框架 的 Controller 明确禁止 Update + 协程 就是为了倒逼业务下沉。

Layer 数量爆炸（20+ 层）

见过项目把 Layer 拆到 20+，最后维护不动。5-6 个 Layer 已够 99% 项目。复杂排序需求用 sortOrder 在 Layer 内细分，不要无限加 Layer。

全局 Time.timeScale 暂停 UI

Time.timeScale = 0 暂停 Update + 物理 + 协程，但 unscaled 动画 + 网络心跳不会停 → 异步流程错乱。 替代：业务级 Pause + 每窗口独立 timeScale（bigcat-framework-BigCat框架 的 GTime 思路）。

await 之后直接用 window 字段

异步加载 + 用户快速点击 → 加载完成时 window 可能已关闭 → NullRef。修法见下面”必须借鉴的设计原则” §reentryId。

把 UIModule 放在 AOT 层

UIModule 涉及大量业务逻辑（窗口配置/布局/交互），放 AOT 后任何 UI 改动都要重新出包，热更失去意义。UIModule 必须在 HotFix 层。证据见 tengine-ui-system-UI系统深度。

必须借鉴的设计原则（不论选哪个选项）

无论你选 A/B/C/D，下面 5 条都应该抄进自己框架——这是源码级共识：

1. 声明式配置（Attribute 或 MonoBehaviour Cfg）

避免”打开窗口前要在 Manager 注册”的样板代码。一处声明 Layer/Path/FullScreen，一目了然。

2. 全屏遮挡优化

一个全屏窗口覆盖时下层 SetActive(false)，节省 draw call。两个层次：

  • 简单版：FullScreen flag + 自顶向下扫描（tengine-ui-system-UI系统深度 §全屏遮挡优化）
  • 进阶版：FullScreen flag + Rect 重叠检测（BigCat Desktop.IsOverlapped）

中小项目用简单版即可。

3. 延迟销毁（HideTimeToClose）

频繁开关同一窗口（如背包反复打开）→ 直接销毁会反复加载 Prefab。

实现方式来源复杂度
标记 hideTime + 列表遍历TEngine低
优先级队列（按 destroyTime 堆顶）BigCat中（更高效）

50 窗口以下用 TEngine 方式；100+ 窗口考虑优先级队列。

4. reentryId 重入检测（强烈建议）

这是 bigcat-framework-BigCat框架 独有但应该普及的模式。没这个机制，异步 UI 几乎必有 NullRef bug。

5. 状态枚举区分 Shutdown vs Terminated

BigCat 7 状态比 TEngine 4 状态更精确——“正在关闭”和”已关闭”是不同语义：

合并为单一 “Closed” 状态会丢失”是否能 Reopen”的判断信息。

看场景借鉴（仅特定情景需要）

6. Desktop 多桌面（仅 MMO/SLG/编辑器）

bigcat-framework-BigCat框架 独有。“主城 vs 战斗 vs 副本”场景明显切换的项目可借鉴。普通项目用 Layer 分组就够。

7. 数据模型解析（dataAddress 字符串）

策划在 Inspector 配 "player.bag.equipment[0]" → 自动绑定数据。需先沉淀 IAggregationModel 规范，中小项目大概率不值得做。

8. 每窗口独立时间轴 GTime

仅当你需要”暂停某个窗口而不影响游戏世界”时考虑。例如：暂停弹窗时游戏继续；或战斗 UI 慢放回放时世界正常。

与 v2 决策 6（事件系统）的协同

UI 间通信选什么总线，由 v2 决策 6 决定。但UI 内部的状态切换不要用事件总线——用心跳 + Controller 处理。这是 bigcat-framework-BigCat框架 的 Controller 禁止 Update + 协程的理由：

反馈环：v3 卡住时回看 v1+v2

如果决策 10 卡住…可能 v1/v2 决策错了
UI 抽象怎么选都不对范式选错了（决策 0）；ECS 范式不应用 OOP 的 Window 抽象
UI 间通信脏乱差事件系统选错了（决策 6）——可能需要补 BigCat 的”心跳为主”思路
UI 状态机失控是否把业务塞进了 Window 类？拆 Controller / Component
HotFix UI 修不动 AOT 服务决策 5 程序集分层切割错了
UI Item（背包格子）GC 高决策 8 对象池没覆盖 UI Item
